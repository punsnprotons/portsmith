# Real-repository transfer benchmark

Two selected integration tasks, run locally on 14 October 2026 (Singapore). These are measured examples, not a success-rate estimate or evidence of parity with Rea. Original upstream clones remain unchanged. No code was published.

## Measured integration results

| Destination | Callable cases before → after | Regression tests | Chromium scenarios | Required commands |
| --- | --- | --- | --- | --- |
| IT-Tools | 0/11 → **11/11** | **138 existing tests** in 33 Vitest files, baseline and candidate | 3 feature + 2 regression scenarios pass on candidate; existing behavior passes on baseline | Upstream type check and production build pass on both |
| TodoMVC ES6 | 2/7 → **7/7** | **3 authored regression tests**, baseline and candidate | 3 feature + 2 regression scenarios pass on candidate; existing behavior passes on baseline | Upstream production build passes on both |

Both final runs use verification version 4 and export checked patches. Final-session proposals are model-generated; setup corrections, earlier failed proposals and the precision contract revision below are excluded from any first-attempt success claim. An additional 400 generated byte/precision cases and 250 generated title cases passed after integration; these inputs were not supplied to the model. They compare against the pinned source library and are supplemental evidence, not independent proofs of library correctness.

Both patches were applied in fresh Git repositories, reproduced their candidate inventories exactly, passed their unchanged full contracts again, and passed browser checks against their production bundles. Replay uses the validated installed dependencies through links; it rebuilds code from the patch but is not a clean-room dependency installation.

## Tasks and setup

**IT-Tools:** replace the existing byte formatter with pretty-bytes' SI formatting, including zero, sub-byte and negative values. The original text-statistics UI calls this function without a replacement UI. The contract declares the intentional units change: 1,000 bytes displays `1 kB`; 250 emoji also occupy 1,000 UTF-8 bytes. Eleven callable cases (including explicit precision), three UI feature scenarios, two UI regression scenarios, all 33 existing Vitest files (138 tests), upstream TypeScript checking and the production build are required. The pre-benchmark production build and Vite warmup generate upstream component declarations in `components.d.ts`; this setup change is frozen, not counted as an integration edit. An earlier run that omitted the full build failed the integrity gate when generation changed its baseline. Its original target copy was restored; the complete setup uses a new target copy.

**TodoMVC:** replace its existing title escaper with escape-html. The original implementation omits entity terminators: titles such as `'face` and `` `A `` render incorrectly. A frozen test bridge under `test/portsmith-boundary.mjs` invokes the original `Template.show()` and extracts the label HTML; it contains no replacement escaping. Three authored Node regression tests check existing renderer behavior, and two authored browser regressions exercise adding, completing, filtering and clearing todos. These are **not claimed to be TodoMVC's upstream Cypress suite**. Seven callable cases, three UI feature scenarios and the original production build are also required. A protected Webpack wrapper serves unchanged `todomvc-common/base.js` and upstream `learn.json` locally, disables dev-server reload sockets, and retains the real app entry, styles and template. The repository's root license is included with the example.

All assertions are written before model edits. Extending a contract creates a fresh run; old failed runs remain available. GPT-5.6 Terra generates integration proposals through the configured API. Neither success is an authored integration proposal.

## Failures retained and fixes

1. The old regression adapter could not represent IT-Tools' existing Vitest suite. A real Vitest 0.34 completion adapter now counts tests, rejects missing/expanded file selection, errors, skips, TODOs, empty suites, crashes and incomplete results. It currently supports **0.34.x only**.
2. Sending the entire larger app is wasteful and omits Vue in the old context selector. Optional `contextFiles` now includes explicit UI files, always includes the callable entry, transferred feature and declared regression files, and records omitted paths. It never silently truncates selected files. Full verification logs remain local; model feedback uses bounded diagnostic tails.
3. IT-Tools' first model proposal used the app's `@/` alias, which the native Node callable boundary cannot resolve. The integration gate rejected it and the model repaired the import. The model instruction now explains that boundary.
4. IT-Tools passed the original behavior/UI contract and bundled successfully, but the separate upstream type check failed with TS7016: the transferred JavaScript was missing its adjacent `.d.ts`. The extractor now retains original adjacent declarations and keeps runtime files when TypeScript resolution prefers declarations. A fresh contract adds both type checking and production building; the earlier patch is not presented as the final result.
5. The first IT-Tools contract containing production build checks stopped before model calls because the build generated additional component types in its baseline. Full upstream generation now runs before preparation in a fresh target, preserving the failed attempt and its original target.
6. TodoMVC's first preflight rejected incorrect Webpack static-directory CLI arguments. No model call was made. A fresh run uses a frozen server configuration wrapper. Assertions were retained.

Additional declared `checks` require successful completion on baseline and candidate and use verification version 4. They supplement structured regression evidence; arbitrary exit-zero commands cannot replace the regression test adapter. Test, Vite/Vitest/Webpack and TypeScript configuration files are protected from adaptation.

## Reproduce

Read the pinned repositories before executing them. These commands execute their code on the host; snapshots and child processes are not a security sandbox. The live adaptation transmits selected source to your model provider and consumes API usage.

Use a fresh `.portsmith/github-bench` directory. Clone the four repositories into `repos/it-tools`, `repos/pretty-bytes`, `repos/todomvc`, and `repos/escape-html` and check out the exact commits above. Copy IT-Tools into `targets/it-tools`, and TodoMVC's `examples/javascript-es6` into `targets/todomvc-es6`. Preserve the source clones unchanged.

```sh
# Install in each disposable target, not in the source clones.
(cd .portsmith/github-bench/targets/it-tools && npx --yes pnpm@9.11.0 install --frozen-lockfile --ignore-scripts)
(cd .portsmith/github-bench/targets/todomvc-es6 && npm ci --ignore-scripts)

node scripts/benchmark-github.mjs --case it-tools --mode warmup
node scripts/benchmark-github.mjs --case it-tools --mode prepare
node --env-file=.env scripts/benchmark-github.mjs --case it-tools --mode run

node scripts/benchmark-github.mjs --case todomvc-es6 --mode prepare
node --env-file=.env scripts/benchmark-github.mjs --case todomvc-es6 --mode run
```

Preparation uses fresh directories, copies installed dependency trees, freezes all contracts and records explicit model context in each run's `model.json`. It can take several minutes and several GB for IT-Tools. The `*-latest.json` files point to each run. `verification.json`, `autonomy-*/summary.json`, proposals, screenshots, traces and patches retain the underlying evidence. `--mode run` is bounded to three model attempts.

Remaining limits include manual environment setup, explicit contracts/context selection, native Node callable boundaries, unsupported bundler aliases in extracted features, one supported Vitest release family, and Chromium-only browser checks. This benchmark does not establish general cross-framework, monorepo, deployment or production reliability.

A later preflight also rejected a benchmark-environment mistake: a packaging JSON report was temporarily named `package.json` above the app. Esbuild attempted to read it as a manifest. The report was renamed `package-audit.json`; all frozen app inputs and assertions stayed unchanged, and the failed preflight remains recorded. No provider call occurred in that attempt.

The IT-Tools dependency-link shortcut passed verification but was rejected by adaptation, consuming three bounded model attempts without changing the candidate. Real dependency copies replaced the links. Portsmith now diagnoses this unsupported setup before any model request, and the benchmark resolves a linked installation to its real path before copying. The frozen contract and application files did not change.

The first build-safe IT-Tools proposal ignored the pre-existing precision argument. A supplemental review found three failing precision cases. A new run retains all eight original cases and adds explicit 0/1/2 fraction-digit expectations from the source library. Earlier contracts and evidence were not edited.
